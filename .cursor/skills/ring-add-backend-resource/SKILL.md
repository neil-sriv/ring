# Adding a backend resource to Ring

Use this checklist when introducing a new domain entity or endpoint to the
FastAPI backend. Mirror existing patterns from
[ring/parties/](../../../ring/parties/) and
[ring/letters/](../../../ring/letters/) rather than inventing a new layout.

## Workflow

```
Task progress:
- [ ] Pick or create the domain package
- [ ] Add the SQLAlchemy model
- [ ] Add Pydantic schemas
- [ ] Add CRUD helpers
- [ ] Add the FastAPI router
- [ ] Register the router in ring/fastapp/routes.py
- [ ] Generate and apply an Alembic migration
- [ ] Add authz checks where applicable
- [ ] Add unit tests and a factory
```

### 1. Pick the domain package

If the resource fits an existing domain (e.g. another letter-related thing),
put it under `ring/<domain>/`. Otherwise create
`ring/<new_domain>/{api,crud,models,schemas}/` to match the existing shape.

### 2. Model

In `ring/<domain>/models/<resource>_model.py`:

- Inherit `Base, PydanticModel, APIIdentified, CreatedAtMixin` (see
  [ring/parties/models/group_model.py](../../../ring/parties/models/group_model.py)).
- Add a new entry to `APIPrefix` in
  [ring/api_identifier/api_identified_model.py](../../../ring/api_identifier/api_identified_model.py)
  (3–6 chars, lowercase).
- Decorate the class with `@register_api_class(APIPrefix.X)`.
- Set `API_ID_PREFIX` and `PYDANTIC_MODEL` on the class.

For entities that attach to many different parent types, prefer a **weak
reference** column `target_api_id: Mapped[str]` over a polymorphic FK; resolve
the parent with `bulk_get_models`. Prefer hard deletes over soft-delete flags.

### 3. Schemas

In `ring/<domain>/schemas/<resource>.py`, define request and response Pydantic
models. Match the snake_case field names from the model.

### 4. CRUD

In `ring/<domain>/crud/<resource>.py`, expose pure functions that take a
`Session` and return ORM instances. Reuse `get_model`, `get_models`,
`bulk_get_models` from `ring/api_identifier/util.py` for lookups by
`api_identifier`.

### 5. API router

In `ring/<domain>/api/<resource>.py`:

```python
from fastapi import APIRouter, Depends
from sqlalchemy.orm import Session

router = APIRouter()


@router.post("/<resource>")
def create_<resource>(
    payload: <Resource>Create,
    db: Session = Depends(get_db),
    user: User = Depends(get_current_user),
) -> <Resource>Response:
    # authz check (see ring-authz-checklist skill)
    ...
```

### 6. Wire the router

Add a single `router.include_router(...)` line in
[ring/fastapp/routes.py](../../../ring/fastapp/routes.py) with the right
`prefix` and `tags`.

### 7. Migration

```bash
ring db generate "add <resource>"
ring db upgrade
```

Inspect the autogenerated revision under `ring/alembic/versions/` before
running `upgrade` — autogenerate sometimes drops/recreates columns it
shouldn't.

### 8. Authz

If the resource is user-scoped, call `load_and_check` or `bulk_load_and_check`
from `ring/authz/authz.py` before reads and writes. Follow the
`ring-authz-checklist` skill.

### 9. Tests

- Add a factory in `ring/tests/factories/<domain>/`.
- Add unit tests under `ring/tests/unit/<domain>/` covering create, read,
  permission-denied, and not-found paths.
- Use the `admin` marker (see [ring/tests/pytest.ini](../../../ring/tests/pytest.ini))
  when an authenticated admin client is needed.

Run with:

```bash
ring test run
```

## After the backend lands

The OpenAPI surface has changed. Regenerate the frontend client per the
`ring-regen-frontend-client` skill, then either follow `ring-split-pr` to land
the frontend separately or continue in the same branch.
