# Ring Alembic migrations

Always generate the revision skeleton with the Ring CLI. **Never hand-author a
file in `ring/alembic/versions/` with a made-up `revision` id or `down_revision`.**
The CLI produces a real random revision hash, wires `down_revision` to the
current head, and autogenerates the diff from your model changes.

## Workflow

```
- [ ] Make the SQLAlchemy model/column change first
- [ ] Generate the revision via the CLI (never by hand)
- [ ] Inspect the autogenerated file under ring/alembic/versions/
- [ ] Edit the body if autogenerate missed raw DDL (see below)
- [ ] Apply with the CLI
```

### Local machine

```bash
ring db generate "<short message>"   # alembic revision --autogenerate
ring db upgrade                      # alembic upgrade head
```

### Cursor Cloud Agent VM

The `ring` CLI may not wrap compose here, and Docker needs `sudo`:

```bash
sudo docker compose -f compose.core.yml -f compose.dev.yml --profile dev \
  exec -w /src/ring api alembic revision --autogenerate -m "<short message>"

sudo docker compose -f compose.core.yml -f compose.dev.yml --profile dev \
  exec -w /src/ring api alembic upgrade head
```

Both run alembic **inside the `api` container**, which has DB access and the
app's metadata. Running `alembic` from the host venv will not work.

## Always inspect the autogenerated revision

Autogenerate compares ORM metadata to the live DB and is imperfect. Before
`upgrade`, open the new file and check it:

- It may **drop and recreate** columns it should only alter — fix to a plain
  `op.alter_column(...)`.
- It does **not** detect raw DDL. CockroachDB-specific objects in this repo are
  written with `op.execute(...)`, not Alembic ops:
  - `CREATE INVERTED INDEX` (full-text `text_tsv`)
  - `CREATE VECTOR INDEX ... vector_l2_ops` (embeddings)
  - `STORED` computed columns (e.g. `text_tsv AS (to_tsvector(...)) STORED`)
- If your change is one of these, still create the skeleton with the CLI (so
  the revision id and `down_revision` are correct), then replace the body with
  `op.execute("""<DDL>""")` for both `upgrade()` and `downgrade()`. See
  `ring/alembic/versions/c8ebbe0240e5_replace_text_tsv_with_computed_column.py`
  and `b3b636b1af58_add_search_indexing_to_db.py` for the pattern.

## CockroachDB gotchas

- **Vector index cluster setting** must be enabled before vector-index
  migrations succeed (one-time, after `ring-cockroach` first starts):

  ```bash
  sudo docker exec ring-cockroach ./cockroach sql \
    --certs-dir=/root/.cockroach-certs -d ring \
    -e "SET CLUSTER SETTING feature.vector_index.enabled = true;"
  ```

- `DROP NOT NULL` is allowed on a column that backs a vector index; you do not
  need to drop the index first.

## If you cannot run the CLI

If the stack/container is unavailable and you must write the file by hand:

1. Find the current head: it is the one `revision` not referenced as any other
   file's `down_revision` in `ring/alembic/versions/`.
2. Set the new file's `down_revision` to that head.
3. Generate a real-looking 12-char hex `revision` id (do not reuse an existing
   one or use a sequential placeholder).
4. Flag clearly that the file was hand-written and should be regenerated with
   `ring db generate` once the stack is available, so the revision id matches
   Alembic's convention.
